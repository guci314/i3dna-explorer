# i3dna explorer 快速入门

> 用一个最小例子走完核心概念：创建一个场所 → 定义一个类 → 声明一个方法 → 点火一次。
> 读完本文（约 10 分钟）后再去读 ARCHITECTURE.md 的详细章节。

## 前置知识

你需要知道：文件系统（目录/文件）、JSON/YAML（配置格式）、基本的业务流程概念（审批/办结）。
不需要：Petri 网理论、DDD、Spring 框架——本文会用类比说明。

## 从一个故事开始

假设你是一个银行的系统管理员。你要在 i3dna 目录树上建一个"转账"业务：

1. **有人提交转账申请**（一张单据落到目录里）
2. **系统自动扣款**（吃掉单据，更新余额）
3. **系统自动入账**（再吃一张单据，更新对方余额）
4. **结账检查**（确认所有单据都处理完了）

这个流程在 i3dna 里长什么样？

## 第一步：看懂目录树

```
企业/                          ← 根场所（整个公司）
├── 域/
│   └── 银行/                  ← 域 = Java package，静态组织类
│       └── 类/
│           ├── 人员/           ← 实体类（有什么）
│           │   ├── 类.md       ← 类定义
│           │   ├── schema.md   ← 字段共识
│           │   └── 知识/       ← 领域知识
│           └── 转账/           ← 过程类（做什么）
│               ├── 类.md
│               └── 方法/
│                   └── 扣款.md  ← 方法 = Petri 网的变迁
├── 场所/
│   └── 广州营业厅.md           ← 场所 = bounded context
├── 实例/                       ← 运行时数据
│   ├── 人员/
│   │   ├── 刘亦菲/
│   │   │   └── 档案.md         ← 账簿（状态槽）：余额等
│   │   └── 刘德华/
│   │       └── 档案.md
│   └── 转账/
│       └── 转账001/            ← 案卷（过程 bean 的工作区）
│           ├── 申请.md         ← 单据（消息槽）
│           └── __账/
│               └── 扣款/
│                   └── __结果.json  ← 账 = 发射史
```

## 第二步：理解账簿和单据

**账簿（状态槽）**——住文件，一户一页：
- `实例/人员/刘亦菲/档案.md` 里有 `余额: 900`
- 最新版算数，旧版留痕在 git
- 命题：看账不销账——被反复读

**单据（消息槽）**——住目录，一沓共存：
- `实例/转账/转账001/扣款单__001.md` 是一张单
- 办完一张核销一张（消费即删）
- 命题：使命是被核销

**形状定律**：账簿住文件，单据住目录。弧指文件是读/写一个值，弧指目录是发/收单据。

## 第三步：理解点火

点火 = 柜员办一笔业务。三步原子提交：

```
1. 暂存：agent 把产物写到临时目录，正树不动
2. 验收：引擎逐产物检查，缺文件/空文件 = 失败
3. 落位：os.replace 到正树（原子替换）
```

一次点火：**吃一张单（输入弧），写一笔账（产物弧），记一条账**。

## 第四步：理解弧

弧 = 变迁的腿，两条：

| 类型 | 方向 | 例子 |
|---|---|---|
| 输入弧 | 指向条件 | "扣款单必须到场才使能" |
| 产物弧 | 指向产出 | "扣款成功后更新余额、开出入账单" |

弧声明在 `任务.md` 里，是唯一事实源。UI 投影（树节点颜色、工位面板、血缘高亮）全部从弧现推导——零第二登记。

## 第五步：理解一致性

**转账全程**：
1. 开单：人提交转账 → 树上开出"扣款单"（承诺：要扣 100）
2. 扣款点火：吃掉扣款单 → 余额 -100 → 开出"入账单"（承诺：要加 100）
3. 入账点火：吃掉入账单 → 余额 +100（承诺兑现）
4. 结账：lint 查单据是否清零

**一致性破坏**：如果第 2 步后系统停了——扣款单已删，余额已改，但入账单还在。结账时 lint 报错：「残单就是现场」。

## 第六步：理解自举

知识住树不住脑：
- **纪律卡**在 `目录树元知识/知识/` 目录下
- **类型文件**在 `消息/*.md` 定义单据格式
- **校验程序**在 `目录树元知识/校验程序/` 可执行自检

agent 的 prompt 每轮从树重组装——上下文工程就是泰勒的工时研究。

变更全部案卷化：
- M0 点火：任务=变迁（生成代码与测试）
- 结构拓扑：女娲.立场所/撤并场所
- M1 类手术：女娲七法（立域/立场所/立类/加方法/改弧/封类/撤并场所）

连女娲自己的手术也走女娲的案卷（quine）。

## 核心术语速查

| 账房话 | 物理话 | 一句话 |
|---|---|---|
| 账簿 | 费米子槽/状态槽 | 一户一页，最新版算数 |
| 单据 | 玻色子槽/消息槽 | 一沓共存，办完核销 |
| 票据夹 | 主题目录 | 夹子定类型 |
| 票号 | uuid | 账房从不靠票面标题认票 |
| 盘存 | marking | 此刻柜里几本账、夹里几张单 |
| 日结 | 悬账门/结账清零 | 单据全核销才打烊 |
| 柜员办一笔 | 点火 | 吃一张单、写一笔账 |
