## 消息模型层

### 3. 同实例多轮请求会互相覆盖（8-19 实证如文，界比文窄）——已修·修订 2

8-20：104号 工单顺号量子化 → 同日修订 2/工单106 换判据。同名必覆盖（{案卷号} 是文件名唯一变量、os.replace 落盘）逐字复现；多实例互不覆盖属实。修订 1 判据「跨主角＝非本任务输入的消息」有洞：文件弧按固定名消费的单（审查单/持有单）被误编号 `__rN`——消费者永远读不到新单、销单按名则 r2 锁永不释放。修订 2＝**顺号是消息类型的投递属性**（要式性）：类型文件（消息/<单名>.md）frontmatter 声明 `顺号: 真` 才启用，默认关闭（＝现状行为，安全兜底）；声明者同名 `__rN` 共存（每次发射＝一张新单）＋缺席免收回（本次没开≠撤销前次）＋缺席火不认领前火之单入账，未声明者（含跨主角文件弧消费的单）固定名翻页/收回不动。配套：类型件查找按 `__` 段剥后缀寻种（消息/请求审查单.md 命中 请求审查单__X__r2.md——带案卷号后缀的单此前寻不到种，is_message 恒假）；两车道（write/stdout）同修，账记顺号实名（落位表同步，防 lint 虚报漂移）；lint 防错配门——顺号类型的消费弧是文件弧 → 警告应改目录弧（否则 __rN 单错配）；m1 仅 消息/请求审查单.md 声明顺号（目录弧收件箱消费）〔8-21 审查类并入研发，信箱车道撤除——该样板已删，m1 归零顺号声明，机制与 lint 门保留；同日形状定律（§1）裁定顺号退役为过渡方言——多单共存的正解是目录槽＋uuid〕。残余：`__rN` 是身份不是顺序承诺（字典序 r10<r2）；并发抢名非原子（缺陷 1 纪区）；收件箱「消费即删」仍靠 agent 指令不执法（缺陷 15 候选，另案）。

### 4. 死信没有去处（8-19 实证如文，痕迹比文更少）

喂非法单走审查管线：单子照常消费、全网络零站要动、lint 无声——均如文。且死信在全机制里**零持久痕迹**：点火账记不出消费过哪张单（目录槽缺陷已由 §8.12 盘点单修复——新火可证「收件箱当时有哪张单」）；唯一回执审查报告是单槽文件，连续两张死信互相抹掉前一张。**主题车道回执已闭（8-21 工单2）**：消费清单记「哪一火吃了哪张单」（uuid 名＋sha256——票号身份零碰撞，连续两张不互抹），点火账从此说得出消费过哪张单。修复方向已定型（8-20，账房原型＝票据法拒绝证书）：**驳回单**消息类型（append-only；键=被驳回单/案卷号/驳回理由/驳回人署名；法定路径=落回开单方案卷槽，镜像持有单形）——引擎零改动（普通产物弧即可落），接线归各审查站任务声明；类型文件待立（模板已备，随手术面增补同批入基线）。

## 工程层

### 5. PyQt6 被非终端父进程启动时的崩溃链（8-19 实证如文）

i3x 缓解在位（.zshrc 持久定义，stdout/stderr 直通＋tee /tmp/i3x.log）；猎证顺带发现 `explorer-开演前检查单.md` 曾教缓解前的旧裸命令直启——**已改**（8-19 落：检查单现教 `i3x` 启动并引用本条）。根治待 PyQt6 修或绕开该宿主。

### 6. 历史账漂移（8-19 比文更糟）

演示树半边成立：trade-v4 漂移 16/缺席 8、trade-v2 漂移 9/缺席 5 均为迁入前旧物，trade-demo 全净。但 m1 的 35 漂移/6 缺席里有**迁移后新产生的**（K1 链改装、执行程序搬家后账内旧路径）——不纯是历史负债，每次 lint 的噪音在生长。推进自平仍是正解，但「迁移即清账」该成为迁移动作的收尾步。

### 7. 持有单死锁不设防（8-19 实证如文）

持有检查只在规划层（_task_needs_fire），fire/settle 不查——互持双单不会死锁进程，但被持有挡住的任务 need=False 永不入 converge 的未收敛清单，死锁**永远静默退 0**。单人人工排序可解；多人需死锁检测或超时，暂不建。

### 12. 目录输入弧永不入账 → converge 永不收敛（8-19 猎证发现，已修）

**修法**：账记「盘点单」。原状：cmd_run 只记 isfile 输入，目录弧（收件箱、类目录）永不进账 → needs_fire 恒判「声明输入未入账」重复点火到退 3——单进程即中招；也是缺陷 4 死信零痕迹的共因。**修法（8-19 裁定：盘点单而非索引文件——索引是会说谎的登记，盘上真值才可对账）**：目录弧入账为 `{名称, 目录:真, 清单:{文件:sha}}`，三条设计钉——①**收盘盘点**（记点火后清单，消费即删的收件箱不落永久漂移）；②`__`/点前缀目录不入（账不进账，账不能是自己的输入）；③粒度过宽归声明者（类目录当输入=类内任何文件变都重算，保守侧；嫌吵收窄弧）。目录已变＝专用催火理由（「目录已变：收件箱」）；lint 盘点对账同形（漂移=警告待重审）。旧账自愈：存量账无目录条目 → 首次 converge 多点一轮火即平。

### 13. 定义底物写仍用固定暂存名（8-20 评审发现，知情豁免）

`i3dna_store.py` 的 `MdDefStore.save_arcs`/`TaskDefMdStore.save_arcs`（改弧落 任务.md）暂存名固定 `.tmp`——与 ARCHITECTURE.md §8.1 账写崩栈同型的并发窗口：并发双女娲改弧可复现 FileNotFoundError 模态。现状靠组织变更低频兜底；真到并发改弧那天，同 §8.1 修法（pid 后缀）。

### 14. 单据契约不在手术面（8-20 定理化推出，账房史证放大；修法待执行）

消息类型文件（消息/*.md——法定路径/契约键所在）不在 lint ⑦ 手术面清单：改法定路径零阻力、不入宪法时刻基线、lint 无感——公理"单据契约值得立法的家"半满足，而人类账房对单据格式的保护是全系统最重（改格式＝立法，私改＝伪造）。修法（diff 已实测验货）：手术面增补 `域/*/类/*/消息/*.md`＋根 `消息/*.md`；m1 现存 12 件随批入领域面大赦表。状态/ 类型文件（状态槽契约）对称待议。

### 15. 收件箱"吃单删除"是嘱咐不是机制（8-20 工单107，B 档已修）

三件实测：审查类吃单后删除只写在任务正文里（给 LLM 的嘱咐，引擎不管）；引擎删除机制够不着收件箱（只删"单文件消息这轮没发射"和"显式回收弧"，目录里的文件两者都不沾）；git 全史零删除记录——嘱咐从未被验证执行过一次。后果两向：**漏删**→单永远在场→审查站永远"有活"反复点火白烧钱；**更糟**：agent 删了单但漏处理其中一张→单没了像"已消费"，实际工作丢失（此向 B 档抓不住，只有 A 档能绑）。根源：弧是静态声明、收件箱是动态集合（文件名含案卷号，火起来才知道），弧没法提前声明要删哪些单，退化成 prose 叮嘱。**B 档已修**（lint 对账扩展）：收盘盘点里的单据过了本火仍在场且 sha 未变 → 警告「疑似漏吃」；不在场（已消费）/ sha 变（新单顶替）/ 非单据 → 静默；§8.12 前旧账无盘点单不点亮。边界如实：同名同内容重开会误报（罕见可接受）。**A 档后置**（等真实用例攒两三个再实施）：agent 不再自己删单——点火产物多一项**消费清单**（本次吃了哪几张），引擎在落位提交点内照清单删、账记「消费清单」节（与回收清单同族）；删除权收归引擎，删单与处理同提交点绑定，两个方向的漏洞一起闭；清单外的单不删（新到不误伤）。**A 档已落·主题车道（8-21 工单2，形状定律行为件）**：目录弧输入指向主题目录（类型声明 `主题:`）→ **一火一单**——引擎选单（字典序最小，确定性可复算）、落位提交点内删单、账记消费清单（{名称, sha256, 消费: 真}，与回收清单同族）；agent 不再自己删单（prompt 只喂选定单一张，消费归引擎声明在案）。与 A 档原设计一处偏差如实记：删除不照 agent 报的清单——选单权也收归引擎（agent 清单可谎报，删别人单洗账面）；回执＝盘点单（§8.12，记点火时队列全量）＋消费清单（记本火吃哪张）合读。老收件箱车道（无主题声明）仍 B 档语义，零迁移；办结（backfill）车道同律消费。

### 16. 起草车道三小洞（8-20 对抗评审攻破，工单108；F1/F3/F4/F2 均已修）

F2 由用户裁定②后工单109 实施。

- **F1 落位非原子（已修）**：`cmd_draft` 直写 `open(tp,"w")`——写一半崩＝槽里半截文件且"人过目"看的是模型发送内容、盘上撕裂无人知。修法＝ARCHITECTURE.md §8.1 同型：pid 暂存＋`os.replace`（并发两 draft 不互撕有钉）。
- **F3 案卷材料可伪造槽文件（已修）**：案卷材料分支只查路径在案卷内——一张草稿可落 `测试/返工单.md`：伪单在场欺骗使能（开发见返工单＝进修复模式），结账被悬账门拦死、案例卡死。修法＝路径含 `消息/`/`状态/` 段或文件名（去 `__` 段寻种）命中树上消息类型名（引擎自建收集器，与 lint 的 `_message_type_names` 判据同源各自实现——独立见证人惯例）→ 拒「那是单据不是材料」。产物槽分支不受影响（弧声明管着）。
- **F4 kv 回退值不规整（已修）**：`_md_fields` 宽容回退逐行切后不剥前导空格不剥引号——同一文件走 YAML 与走回退读出不同值。修法＝strip＋剥成对引号，两种读法对齐（混合形回归钉）。
- **F2 展示-落位无绑定（裁定②已修，工单109）**：流程"模型起草→回显给人→人批准→[draft 落位, settle]"中落位内容来自批准话语信封，模型可在批准步换稿；draft 原本零入账零 journal——换稿前后树上、git、账三处无痕，事后不可证。两案：①人眼绑定（批准编译改 [draft 落位, 重读盘上内容回显, settle]，UI 层多一轮过目）；②journal 留尸（draft 落盘后记一笔 git journal、不写账——尸骸即绑定证据，与"删单不丢证据"同哲学）。**用户 8-20 裁定②**：`_journal` 加 scoped add（只加本次草稿路径，不代别人提交在途文件），message=`起草 <方法目录> 案卷 <案卷号>`，fail-soft 照旧（非 git 树静默）；同槽两稿两笔两尸、`git diff` 即换稿铁证，`__账/` 零新增有钉。

### 17. 回收弧残壳＋对账不认回收清单（8-20 用户实证——真树撤 sample_domain 后树上还在；已修）

回收弧（回收: 真）办结只 `os.remove` 文件：①空目录残壳留在盘上，树面即目录面——空壳渲染成空域节点（法自己写「域从树面消失」未被机制兑现），还触发空域悬空 lint（7→9）；②旧账（立域）的产物清单对着已删文件报「清单文件不存在」——对账面不认回收清单，「封不删＝证据链完整」只对了一半。修法：①`_prune_empty` 随扫——删后空父目录链逐级收走，非空即止（「只吃空域」的机械面）、不越树根；②lint `_recycle_cover`（{(名称, sha)} 盖住集，与产物后账覆盖同模式）——回收清单盖住的缺席＝依法退役（info 留痕，git 历史留尸可对勘），无盖住的真悬空仍报错。三臂引擎钉＋lint 豁免/真悬空双向钉。
